# 更好的实验报告 (agentspace-better-exp-report)

> 基于已记录实验数据写实验报告及其图表的规范 —— 数据通常来自登记 exp 的 exp_data/exp_NNNN/。文字规范适用于工作区内任何技术总结; 实验报告只是要求最严的场合。

## 0. 动笔之前

1. **工具优先** — 先查 utils.md / utils/ 里项目已有的做图工具并复用; 确实没有合适的才新写 matplotlib 脚本。新写的脚本进 utils/ 并登记。
2. **读全量记录** — exp_data 里有完整细节(原始日志、单次运行元数据、配置); 只按汇总表写报告等于浪费当初留下的数据。
3. **认清读者** — 问清或推断报告给谁看(用户本人 / 论文 / issue), 深度与正式程度随读者定。

## 1. 作图

### 1.1 外观

- 默认色盲友好配色(如 Okabe-Ito); 全套图共用一套"系列→颜色"映射 —— 读者只需学一次。
- 每根坐标轴带单位; 刻度疏密可读; 标签与图例字号缩放后仍可读; 无图表垃圾(网格低调、不用 3D、不用彩虹色图)。
- 矢量输出(PDF/SVG)或 ≥300 dpi 的 PNG; 全报告图尺寸一致。
- 默认 matplotlib 栈, 除非项目已标准化在其他栈上 —— 跟随项目。

### 1.2 数据处理

- 先分类再作图 — 主对比 / 消融 / 规模 / 方差; 每张图只回答报告中的一个提问。
- 清洗规则写明, 绝不静默 — 异常值剔除标准连同受影响的运行数一起说明; 被丢弃的运行在正文报告。
- 展示方差 — 误差棒注明 n 与固定语义(整份报告统一 std 或置信区间); 单次运行的数字明确标注是单次。
- 用足数据 — 派生指标(加速比、归一化分数)从原始记录计算, 不目测; 图上每个数字可回溯到 exp_data 下的某个文件。

### 1.3 图内文字

- 自完备的标注 — 图连同图例单独被引用时仍能看懂: 系列有定义("A""B"到底是什么)、条件写明、单位在场。
- 不留裸符号 — 坐标轴叫"x"或图例叫"m3"的单字毫无信息; 写清它们是什么。
- 语言 — 中文标注, 英文仅限社区默认术语, 与 §2 文字规则一致。

## 2. 文字

- **中文为主、英文按需** — 是否保留英文只看一个判据: 该领域社区是否默认使用这个术语; 不设固定英文白名单(任何词表都无法正确覆盖)。社区默认英文的术语(如 throughput、top-1 accuracy)保留英文; 社区惯用中文的术语写中文。既不硬造中文合成词, 也不生造英文。
- **不用歧义缩称** — "门"(gate)、"臂"(arm / expert 路径)这类脱离上下文就没有意义的单字, 换成完整的常见描述或直接用英文术语。
- **完整优先于精简** — 不为省字数压出歧义; 一句更长但清楚的话胜过一句更短但费解的话。精简来自删掉不重要的内容, 绝不来自含糊措辞。
- **自完备(核心规则)** — 阅读者看不到你的记忆与上下文: 每个符号、缩写、条件、字母在首次出现处定义; 每个结论带着它的证据(图/表编号 + exp_data 下的数据路径); 假设写明; 负结果与无结论的结果照报, 不掩埋。

## 3. 结构

- 结论先行 — 报告第一段就给出实验问题的答案, 证据随后。
- 每图配读法 — 图前一两句话告诉读者该注意什么。
- 结论分级 — 数据支持的结论与推测明确分开; 推测显式标注"推测"。
- 溯源 — 每张图/每个表标注数据来源(exp_data 下路径 + examples/exp_spec 内的配置); 每张图都被正文引用, 不放孤图。

## 4. 报告放哪

- 带图的完整报告放 exp_data/exp_NNNN/report.md — 与 exp_data 其余内容一样仅存本机。
- 其执行摘要以自完备文字镜像进 exp 手册的"结果"节: 不放相对图链(对本机以外的读者是死链); 本机指针显式标注(如"图见本机 exp_data/.../report.md")。
