# 更好的实验 (agentspace-better-exp)

> 实验特化的讯问: 在实验开跑、exp 登记之前, 与用户对齐实验设计。工作区机制(exp 脚本、examples/exp_spec/、exp_data/)由项目的 AGENTSPACE AGENTS.md 承担 —— 本 skill 只管思考纪律, 不管文件管道。

## 0. 铁律

1. **仅在确认后启动** — 本 skill 在用户经 agentspace-exp 触发器选择登记该实验之后激活(显式 /agentspace-exp 要求, 或接受了你的一次性提议)。绝不为了发起提议本身而激活; 绝不登记开发收尾的正确性验证。
2. **每次只问一个问题** — 得到回答后再问下一个; 每个问题都附你的推荐答案(讯问者不是空白提问机)。
3. **事实与决策分离** — 能从环境读到的东西(仓库状态、既有配置、tests.md 环境、utils 工具、历史 notes/iterations)一律查, 不问用户。只有真正的决策才交给用户。
4. **无共识不开跑** — 用户确认达成共识之前, 实验既不登记也不运行; 手册的"实验问题与范围"与"假设与预期"两节就是这份共识的书面证据。
5. **先覆盖后深挖** — §1 的每一轴至少触及一次; 只有用户明确说某轴不适用才跳过。

## 1. 五个审讯轴

按序走 —— 早先的回答解锁后续问题。每轴: 点明主题、提问、给出推荐、记录确认的答案。

### 轴 1 — 范围(固定、明确、合理)

- 本实验要回答的那一个问题; 固定的边界(数据集/模型/环境/负载); 以及明确写出范围外的内容。脱离固定测试范围的实验结果没有意义。
- 合理性 — 手上资源(时间/硬件/数据)撑得起这个范围吗? 撑不起的范围不是范围, 是愿望。
- 追问示例 — "哪两个系统之间的哪些数字对比, 能让这个实验一锤定音?"; "如果结果只在半个负载上成立, 你还信吗?"

### 轴 2 — 基线与对照公平

- 拿什么和什么比; 基线是真实的、可复现的、同等调优的 — 两侧同数据、同环境、同测量管线。
- 单变量原则 — 每个对照臂只有一处有意义的差异, 其余全部钉死。
- 种子、重复与方差 — 各臂运行次数相等; 种子列表写进配置; 误差棒语义(std 还是置信区间, 带 n)开跑前定死。
- 追问示例 — "基线数字是与候选同一代码路径、同一测量管线跑出来的, 还是论文里引的?"; "各臂运行次数相等吗?"

### 轴 3 — 测量准确

- 指标定义先钉死 — 精确公式、单位、聚合方式、以及在管线中的哪一步计算。没有钉死定义的数字是不可证伪的。
- 迭代数与 warmup — 量测多少轮、丢弃多少轮 warmup、为什么恰好是这些数。
- 计时口径 — 计时区只包含被测核心目标; 初始化、IO、日志、编译、同步都在区外; 说明可能渗入的开销。
- 环境噪声 — 已知噪声源(争用/温度/后台任务)说明白, 且各臂拉平。
- 追问示例 — "计时括的是 kernel 本身, 还是把 host 到 device 的拷贝也吞进去了?"; "为什么是 10 轮 warmup, 不是 2 轮或 50 轮?"

### 轴 4 — 数据完整

- 汇总 ↔ 细节链 — 每次运行的原始日志落 exp/exp_data/exp_NNNN/, 配置落 examples/exp_spec/exp_NNNN/; 单次运行的元数据(日期/commit/种子/时长)随记。
- 细节要支撑事后复算 — 后续报告(agentspace-better-exp-report)只能和现在留下的数据一样完整。
- 关联 iteration — 已存在于 iteration_NNNN/data/ 的产物复制进 exp_data; exp_data 是权威全量记录。
- 追问示例 — "下周某个数字看着不对劲, 哪个文件能告诉你它出自哪个种子、哪个 commit?"; "别人能只凭这些文件重建出汇总表吗?"

### 轴 5 — 可复现与终止

- 精确命令记进手册; 测试用关键仓库 commit 以点形式记录(关闭时经 complete-exp.sh --commit 记 repo@sha)。
- 成功判据与证伪判据开跑前写死("假设与预期"节); 预算与终止条件(时长/成本上限, "出现 X 即停")。
- 先跑 pilot — 全量预算烧掉之前, 先来一次端到端小规模试跑(暴露管线 bug, 校准真实时长)。
- 追问示例 — "什么结果会让你彻底放弃这个方向 —— 写下来了吗?"; "一次崩溃最多可能损失多长的运行?"

## 2. 产出契约

把确认后的答案沉淀进 exp 手册(templates/exp-manual.md):

- "实验问题与范围" ← 轴 1; "假设与预期" ← 轴 5(判据 + 预算); "方案与配置" ← 轴 2–3, examples/exp_spec/exp_NNNN/ 内每个配置文件一行说明登记。

然后登记 — `scripts/new-exp.sh "标题" [--plan NNNN] [--iteration NNNN]`(标题 slug 规则与 plan 相同 — 小写英文单词、数字、单个连字符)。开跑与关闭遵循工作区 AGENTS.md 的 exp 模块节。

## 3. 边界

- 本 skill 不替代 plan/iteration 流程 —— plan 内代码变更附带的测量仍发生在 iteration 里; exp 只负责实验记录。
- 报告与作图归 agentspace-better-exp-report。
- 对齐中途用户放弃登记 — 停止; 实验照常进行但不记录, 且同一会话内不再重复提议。
